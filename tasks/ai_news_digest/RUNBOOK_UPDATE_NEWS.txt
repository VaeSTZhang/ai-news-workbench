更新新闻 命令运行手册

一、命令入口
- 当用户输入：更新新闻
- 该命令等价于：执行每日新闻更新流程（daily only）
- 可由 OpenCode、Codex、其他本地自动化代理或人工脚本执行

二、日期规则（北京时间）
- 自动读取当前北京时间日期。
- 被总结日期固定为前一天。
- 示例：若执行日为 2026-05-03，则日报总结 2026-05-02。
- 严禁混入旧月份内容、月报条目、长期趋势、方法论、模板规则、采集规则。

三、栏目规则（必须同时处理）
- global_ai（全球 AI 热点新闻）
- chinese_short_drama（国内爆款短剧排行榜与流行趋势）
- 每次更新必须两个栏目同时完成，不能只更新一个。

四、输出路径与文件（daily）
- `tasks/ai_news_digest/news_reports/global_ai/daily/YYYY-MM/YYYY-MM-DD/`
- `tasks/ai_news_digest/news_reports/chinese_short_drama/daily/YYYY-MM/YYYY-MM-DD/`

每个栏目目录必须包含：
- `YYYY-MM-DD_<category>_daily.html`
- `YYYY-MM-DD_<category>_daily.docx`
- `sources.json`
- `task_log.txt`

五、内容质量规则
1) 条目结构（新闻条目或正式说明块）
- 事件标题
- 日期/平台/公司
- 发生了什么（2-4句）
- 为什么重要（1-3句）
- 对 ManJuFlow 的启发（1-3句）
- 来源链接

2) 条目口径
- 日报主列表仅允许：真实新闻、榜单动态、平台动作、公司公告、监管发布、公开报道、可核验业务变化。
- 禁止写成新闻：方法论、采集策略、来源规则、模板规则、安全规则、自动化说明、旧月份内容。

3) 禁止伪新闻条目（明确禁止以下内容进入新闻主列表）：
- 监测说明
- 方法论
- 采集策略
- 来源不足说明
- 双来源规则
- 模板规则
- 自动化说明
- 长期趋势空话
- "今日无重大新闻"
- "公开榜单入口有限"
- "建议持续关注"
- "本期未发现足够新闻"
- 任何只有首页/频道页支撑的泛化判断

这些内容只能写入 task_log.txt 或摘要区，不能作为新闻卡片。

4) 数量目标与不足处理
- global_ai 目标 >=10（新闻多时 10-15）
- chinese_short_drama 目标 >=8
- 若前一天公开可核验信息不足，可少于目标。
- HTML/DOCX 必须使用正式读者说明，不得出现"主列表为空/整改版/已剔除/见task_log"等内部话术。

5) 信息不足时的处理策略
- 如果 global_ai 当天真实可核验新闻少于 3 条，或 chinese_short_drama 当天真实可核验有效内容少于 3 条：
  - 不生成伪完整日报；
  - 可以生成"低信息量日报"，但主列表只放真实条目；
  - 摘要区说明信息不足；
  - task_log.txt 详细记录检索范围、剔除原因；
  - 不允许为了达到数量目标使用旧新闻、月报内容、方法论、模板说明或泛来源；
  - 如果 0 条真实可核验内容，则不要生成正式 HTML/DOCX 报告，只生成 task_log.txt 记录，并在 CLEANUP_NOTES.txt 记录本次未生成原因。

六、来源规则
- 每条必须逐条可访问、可核验、直接支撑正文。
- 不可用来源：打不开、需登录、泛入口、不对应正文。
- 禁止泛来源：不允许只用首页、频道页、搜索结果页、平台入口页作为正式来源。
- 综合趋势观察至少需要 2 个直接相关来源。
- HTML：每条卡片底部提供可点击来源。
- DOCX：每条下方写"来源：标题 - URL"。
- `sources.json` 每条至少包含：
  id, category, title, url, publisher, published_date, accessed_date, used_in_section, reliability_note。

七、格式规则
- HTML 不使用外部 CSS/JS/字体/图片。
- DOCX 不插入图片。
- HTML 卡片字段顺序：
  标题 -> 日期/平台/公司 -> 发生了什么 -> 为什么重要 -> 对 ManJuFlow 的启发 -> 来源链接。

八、task_log 必填
- 执行日期
- 被总结日期
- 栏目
- 目标条数
- 实际纳入条数
- 来源检查结果
- 剔除原因
- 是否发现旧日期内容
- 是否发现方法论伪新闻
- 是否完成 HTML/DOCX/sources.json 输出
- 是否完成敏感信息检查

九、执行完成后的检查
1) 质量检查
- 两个栏目是否都已处理
- 是否仅包含前一天内容
- 是否混入旧月份内容
- 是否存在方法论伪新闻
- 来源是否可访问且对应正文

2) 样例报告与验收
- 生成报告后必须检查 HTML/DOCX/sources.json/task_log.txt
- 质量不达标的日报不得进入正式 news_reports
- 低质量试运行产物移入 archive_old_outputs 并记录 CLEANUP_NOTES
- 提交前必须做敏感信息检查和 git diff 检查

3) 安全检查
- 公开文件不得包含：本机用户名、绝对路径、Desktop、Documents、Downloads、.ssh、.codex、.config、.env、API Key、token、cookie、password。

4) Git 检查与提交
- `git status`
- `git diff --stat`
- `git diff`
- 确认不提交 `archive_old_outputs`、`private_excluded`、敏感文件、本地配置或无用中间产物。
- 通过后执行：
  `git add`
  `git commit -m "chore: add update news command runbook"`
  `git pull --rebase origin main`
  `git push origin main`
